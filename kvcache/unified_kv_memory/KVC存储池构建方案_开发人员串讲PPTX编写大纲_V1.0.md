## 一、串讲定位与组织方式

建议采用 **24 页主讲、8 页备查，主讲约 65 分钟，集中讨论约 15 分钟**。页数和时间为编写建议。听众包括框架接入、对象与目录、通信与存储、调度策略、测试及运维开发人员。

串讲围绕一个固定场景展开：同一租户、同一模型版本的请求复用已封存的连续前缀；源副本位于另一节点，目标显存由推理框架提供；加载成功后接入计算，计算结束后安全释放。在此基础上依次引入多卡、SSD 回源、迁移与失败分支。该场景是讲解用例，不附加未经测量的性能结果。

听众在串讲后应能说明：自己维护哪些状态，通过什么接口协作，哪些事件允许下一步执行，发生错误后由谁处理，以及如何验证实现满足约定。

### 1.1 首次出现的术语

以下词条同时作为演示稿的首次出现释义要求；术语在页标题、图例或正文中首次使用时，保留简短中文说明。

| 术语 | 本次串讲采用的释义 |
|---|---|
| KVCache / KVC | 大模型注意力键值缓存，保存历史 Key 与 Value 状态以复用已经完成的计算 |
| Prefill / Decode | 输入预计算阶段 / 逐字生成阶段 |
| Token | 模型处理与生成文本的基本单位 |
| TTFT / TPOT | 首 Token 响应时间 / 每个输出 Token 的生成耗时 |
| HBM / DDR / NVMe SSD | 设备高带宽显存 / 主机内存 / 通过 NVMe 接口访问的固态存储 |
| KPCL | 封装底层通信能力、承载控制消息与数据传输的接口库 |
| API / I/O | 应用编程接口 / 输入输出，本方案涉及数据读写与传输 |
| TP / rank | 张量并行，将模型张量分到多卡协同计算 / 其中一个工作成员 |
| DMA / Host CPU | 由设备执行的直接内存访问 / 主机中央处理器 |
| DAG | 有向无环依赖图，用于表示任务执行的先后约束 |
| QoS / SLO | 服务质量控制 / 对时延、成功率等的服务等级目标 |
| P99 / QPS | 99% 样本不超过的时延分位数 / 每秒请求数 |
| SR / AR | 可独立交付验收的系统组件 / 组件内部开发工作包 |

## 二、主讲逐页大纲

### P01｜KVC 存储池构建方案

**讲解目标**：建立本次串讲的范围和阅读预期。**时长**：1 分钟。

**页面内容**：

- 主标题：KVC 存储池构建方案；副标题：软件边界、请求路径与实现契约。
- 顶部标注“大模型专项”、方案版本与串讲日期；汇报团队使用实际名称。
- 三张价值卡片：减少重复预计算、扩大温冷缓存保留范围、通过语义与生命周期校验保障消费安全。
- 推进原则：从一套框架、一条真实设备路径和一个对象的完整生命周期开始验证。

**建议图示**：沿用项目白底封面，三张价值卡片各配一句机制说明。首字时延与容量只讲改善方向；“错误消费为零”如出现，标为验证判定要求。

**讲稿展开**：说明本次是构建方案串讲，研发完成度与实测结果需另有证据。

**【核心结论】**：先明确接口与状态责任，再用真实请求验证系统协作。

**来源**：原文 §0、§1、§19.5。

### P02｜业务场景与首版范围

**讲解目标**：区分软件需要覆盖的能力和首个实现闭环。**时长**：2 分钟。

**页面内容**：

- 常见入口：公共前缀、多轮会话恢复、显存压力下的缓存换出与恢复。
- 主讲用例：同租户、同模型、连续前缀，跨节点加载到框架目标显存。
- 首个闭环：一个受支持框架、固定模型布局、一条真实路径，包含失败和安全释放。
- 方案扩展：第二套框架、分层介质与生产管理逐步加入；远端直读等能力按支持清单启用。

**建议图示**：左侧三个业务入口，右侧“首个闭环—后续扩展—条件能力”范围表；公共与私有缓存标出共享域。

**讲稿展开**：池容量用于保留可复用缓存，活跃生成默认使用框架执行显存。收益要同时看请求时延、有效吞吐和资源占用。

**【核心结论】**：首个闭环规模可以小，发布、消费与释放必须完整。

**来源**：原文 §1.1～§1.3、§12.1、§19.5。

### P03｜四层架构与状态责任

**讲解目标**：使不同模块开发人员采用一致的架构和所有权定义。**时长**：3 分钟。

**页面内容**：

- 四层固定为：L1 推理调度、L2 连接器、L3 传输管理、L4 底层传输。
- 管理层处理配置和成员；控制面处理查询、校验、决策；数据面处理正文和完成事件。
- 四类权威状态分别归属管理服务、目录分片、副本所有者和推理框架。
- 框架拥有执行显存和块表；KVC 管理封存对象；KPCL 与平台执行受保护的数据访问。

**建议图示**：以原文 §3.1 为依据重绘四层图，侧边列出四类状态权威；实线标控制调用与结果，正文设备通路单独画出并配图例。

**讲稿展开**：四层是功能责任视角，三面是运行与隔离视角；组件数量不直接决定进程数量。

**【核心结论】**：每类可变状态都有明确权威，跨模块只通过约定更新。

**来源**：原文 §1.2、§3.1～§3.4。

### P04｜部署拓扑与建池流程

**讲解目标**：把架构落到真实节点、进程、资源与启动顺序。**时长**：3 分钟。

**页面内容**：

- 运行库嵌入框架；节点代理管理池资源；目录承载分片；控制器负责配置和运维编排。
- 独立 I/O 执行进程按设备亲和与跨进程缓冲能力选择，无法合法导入时采用进程内执行。
- 资源盘点包含设备连接、共享链路、注册范围、完成语义与故障隔离方式。
- 建池顺序：管理基础→节点探测→划出额度→目录与配置→框架接入→分层验证→开放业务。

**建议图示**：计算节点、存储节点、管理/目录节点三列部署图，底部用短流程带显示建池顺序。节点数以“示意”标注，不写成固定部署规格。

**讲稿展开**：资源捐出必须显式确认，执行显存与池显存共用物理总容量。进程隔离的选择受设备上下文限制。

**【核心结论】**：先验证路径和资源归属，再决定部署形态与开放能力。

**来源**：原文 §4.1～§4.5。

### P05｜一次缓存复用请求的完整路径

**讲解目标**：建立后续专题共用的时序参照。**时长**：4 分钟。

**页面内容**：

- 查询阶段：输入语义和时限，批量查找连续候选，返回版本、位置及成本摘要。
- 准备阶段：检查计划前提，预留目标显存和在途额度，向副本所有者取得源持有。
- 执行阶段：提交传输，取得目标设备可见性，多卡统一本次接入范围，框架在安全点更新块表。
- 结束阶段：源读取结束后释放源持有；目标显存在计算结束后释放。所有中间阶段都保留有界失败出口。

**建议图示**：框架/运行库、目录、所有者、执行器、多卡协调者五泳道时序图。正文传输采用独立粗箭头；查询结果标“候选”，最终结果标“可消费句柄”。

**讲稿展开**：沿原文 §8.4 顺序逐步指图，解释为何源持有和目标缓冲的释放时刻不同。可以分步显示同一图，避免一次出现全部细节。

**【核心结论】**：每个阶段都要提供下一步所需的状态、授权或完成证据。

**来源**：原文 §5.1～§5.5、§8.4、§9.1、§10.3。

### P06｜连接器接口与缓冲生命周期

**讲解目标**：明确框架接入人员和数据执行人员需要共同冻结的契约。**时长**：3 分钟。

**页面内容**：

- 北向接口覆盖协商、模型注册、批量查询、加载、接入、分段发布和释放；代码名进入备查页。
- 目标缓冲包含设备上下文、区域代际、偏移、长度、写权限、布局与计算事件关联方式。
- 源持有保护读取期间的源副本；接入句柄保护计算期间的目标显存。
- 同一目标范围只允许一个有效写尝试；旧操作无法立即停止时，新尝试使用独立目标范围。

**建议图示**：上下两条生命周期带，分别标源持有与目标缓冲的获取、使用和释放；右侧列“成功可接入、需加载、忙/配额受限、取消待排空”四类动作。

**讲稿展开**：重算由框架重新检查算力与显存准入；丢弃旧回调只能保护软件状态，硬件迟到写仍需隔离。

**【核心结论】**：缓冲契约同时约束谁能访问、访问范围和安全释放时刻。

**来源**：原文 §5.2～§5.5。

### P07｜缓存身份与布局兼容

**讲解目标**：说明缓存复用成立的语义条件和实际数据格式条件。**时长**：3 分钟。

**页面内容**：

- 语义键保留模型权重、词表、模板、适配器、位置策略、上文依赖与租户共享域。
- 逻辑对象内容发布后不可变；物理副本迁移独立更新位置、所有者和注册代际。
- 布局清单包括层、头数、块大小、步长、数据类型及多卡分片；转换需要明确支持范围。
- 只有连续、合法、版本一致的范围可复用；同一文本处于不同上文中不能直接共享缓存。

**建议图示**：左侧“语义身份→逻辑对象→物理副本”，右侧三分支兼容判断：直接加载、受测转换、拒绝复用。用一个“相同文段、不同上文”的小例子解释前缀依赖。

**讲稿展开**：六维消费检查是入口，完整身份仍需覆盖实际模型状态。64B 单区间摘要的结构细节留在 A03。

**【核心结论】**：语义与布局均相容，缓存字节才具有可复用意义。

**来源**：原文 §6.1～§6.5。

### P08｜元数据权威与目录查询

**讲解目标**：讲清快路径如何减少查询成本，同时保持授权边界。**时长**：3 分钟。

**页面内容**：

- 元数据按配置、目录、节点资源、请求执行四组展示，各自标明维护者。
- 查询依次利用本地已有句柄、进程缓存、节点镜像与远端批查；结果按连续前缀合并。
- 镜像与过滤器携带代际和提交水位；更新断档时重建，有限过期按预算放弃复用。
- 目录返回候选位置，源访问由有效所有者授权；目录复制与正文复制独立设计。

**建议图示**：左侧查询路径，右侧“状态—权威—副本用途”四行表，候选返回后另画持有申请箭头。

**讲稿展开**：生产三投票副本是待评审建议，原需求 N=2 仍存在配置差异；此处标记，P23 集中讨论。单边远读只作为受测不可变摘要的条件优化。

**【核心结论】**：快查询依赖可追踪的新鲜度，消费授权仍由有效所有者提供。

**来源**：原文 §3.3、§7.1～§7.6、§20.1。

### P09｜对象发布、迁移与安全回收

**讲解目标**：统一对象可见、物理位置切换和资源复用的顺序。**时长**：4 分钟。

**页面内容**：

- 分开维护逻辑对象、物理副本、访问持有和执行任务四组状态。
- 发布时先完成正文与所需证据，再提交目录；确认丢失后通过同一操作标识查结果。
- 迁移先复制到新位置，验证后引导新读者；已有读者继续使用受保护的旧位置。
- 回收先停止新访问，再等设备排空、句柄撤销、软件读者及框架事件退出，最后归还额度。

**建议图示**：主图使用“旧副本—新副本—读者”的迁移时间轴；侧边用短发布链与四组状态说明补足上下文。完整状态表放备注或 A03。

**讲稿展开**：RCU（读-拷贝-更新，用延迟回收保护软件并发读者）只能覆盖软件读者；设备在途访问还需要独立结束证据。超时后仍无法证明静止的区域保持隔离。

**【核心结论】**：资源复用以相关访问全部结束为条件，取消或租约到期只触发回收流程。

**来源**：原文 §7.5、§8.1～§8.7。

### P10｜加载决策与请求准入

**讲解目标**：让策略人员和框架人员理解选路输入、输出和约束。**时长**：3 分钟。

**页面内容**：

- 输入为请求剩余时限、连续候选、布局、路径能力、目标容量及即时在途额度。
- 先排除无权限、失效、布局不兼容和缺少安全完成能力的路径，再计算收益。
- 复用须同时满足：拉取与加载总开销小于本地重算耗时，且剩余计算能满足请求时限。
- 输出本地复用、拷贝到显存、受测远端直读、部分复用或重算建议，并附前提版本与原因。

**建议图示**：输入快照→安全筛选→有限候选比较→资源预留与复核→执行计划。底部标出排队、转换、可见性、接入及多卡等待均计入成本。

**讲稿展开**：Direct-View（远端直读，设备持续读取远端缓存）需计入重复读取与停顿；Copy-to-HBM（拷贝到本地显存）需计入完整搬运与目标空间。计划生成后仍可能失效。

**【核心结论】**：加载同时满足安全、净收益和时限约束后才执行。

**来源**：原文 §5.3、§9.1～§9.5。

### P11｜描述符、异步流水与可见性

**讲解目标**：明确执行器怎样组织工作，以及框架何时可以消费结果。**时长**：4 分钟。

**页面内容**：

- 描述符编译按源目标连续性、权限、布局与后端段数上限拆合并，保持逻辑范围完整。
- 依赖图串联源就绪、读取、转换、目标可见、组决定和计算；重叠范围由真实依赖决定。
- 提交接受、源读取结束、目标设备可见、持久完成、排空完成分别定义可执行动作。
- 部分接受或部分完成保留到票据；未知结果先查询，取消后继续跟踪设备访问。

**建议图示**：上方依赖图，下方“事件→允许动作”五列短表；目标可见事件连到计算，排空事件连到资源复用。避免画成所有完成语义依次升级的统一阶梯。

**讲稿展开**：首版按框架支持选择整段或逐层加载；第一层到齐只允许启动满足依赖的计算，后续层与最慢卡仍可能阻塞。

**【核心结论】**：计算接入需要目标设备可见性，资源回收需要访问结束证据。

**来源**：原文 §6.3、§10.2～§10.5、§12.2。

### P12｜KVC 与 KPCL 的接口分工

**讲解目标**：形成与通信、平台团队联合开发的具体接口入口。**时长**：3 分钟。

**页面内容**：

- KVC 决定对象、范围、副本、目标、优先级和时限，并维护模型语义及对象状态。
- KPCL 提供能力与注册、控制消息、批量提交、可见性、错误、取消排空和实际路径统计。
- 存储扩展边界单列：KPCL 如只提供内存通信，KVC 存储后端承担存储段与命令管理。
- Host CPU 零数据拷贝要求 CPU 不参与正文搬运；绕过主机内存还需证明正文 DMA 不经 DDR。

**建议图示**：KVC 与 KPCL 双侧责任图，中间列契约；底部并排画正文设备直达和显式 DDR 暂存路径，分别列 CPU 正文参与、DDR 正文流量观察项。

**讲稿展开**：接口草图不能写成已发布 API；模拟器验证上层契约，硬件路径与性能通过实际设备验证。

**【核心结论】**：南向契约必须覆盖实际路径、完成范围、反压和安全排空。

**来源**：原文 §1.2、§3.2、§10.1～§10.5、§11.2。

### P13｜分层资源与容量管理

**讲解目标**：说明池怎样扩展容量，以及怎样防止资源重复承诺。**时长**：3 分钟。

**页面内容**：

- 资源按图组织：执行 HBM、池 HBM、不同角色的 DDR、本地 SSD 和远端资源之间逐边登记能力。
- 容量总账同时记录已用、已预留、在途目标、迁移双份、待排空和隔离空间。
- 高水位先限制低价值预取和新增缓存；临界水位保留必要换出及排空资源。
- 淘汰、迁移和预取共同使用总容量与带宽预算；同卡执行显存与池显存不可重复分配。

**建议图示**：左侧沿用原文 §11.1 的资源图并给边标注条件；右侧画无数值的容量组成条和水位动作表。

**讲稿展开**：DDR 可用于元数据、温缓存或显式暂存，是否启用正文角色需要收益依据。原文 70%/85%/95% 水位若上页，标注“已有初始配置，待平台校准”。

**【核心结论】**：可分配容量必须扣除全部已承诺资源和安全回收所需空间。

**来源**：原文 §11.1～§11.4、§13.3。

### P14｜SSD 副本与崩溃恢复

**建议图示**：横向存储段示意加发布顺序，标出三个崩溃点及对应处理；详细格式字段置于备注。

**【核心结论】**：可恢复副本需要正文、清单与提交记录共同成立。

### P15｜多卡状态与生产者交接

### P16｜流量模型与前后台隔离

### P17｜租户隔离与内容完整性

### P18｜故障隔离与恢复顺序

**讲解目标**：把“失败后怎么办”落实到具体故障域与执行责任。**时长**：3 分钟。

**页面内容**：

- 目录失去多数派时停止权威写入，已有有效持有和框架独立缓存按其有效范围继续工作。
- 链路中断时记录部分完成，隔离未知目标，取得安全排空证据后再释放资源。
- 设备上下文丢失交由框架恢复实例，KVC 失效相关句柄与副本。
- 节点恢复采用新启动代际，确认旧设备访问停止，重建注册并校验持久副本后重新服务。

**建议图示**：四行“故障→立即动作→可继续服务→恢复条件”表；旁边列请求停止等待、备用路径服务、实例恢复、安全回收四个时间点。

**讲稿展开**：远端直读只有在平台能证明有界撤销与访问终止时启用。CPU 映射信号不能覆盖全部异步设备故障。

**【核心结论】**：恢复先确认旧访问失效，再以新代际重新提供资源。

**来源**：原文 §8.6～§8.7、§15.1～§15.4。

### P19｜请求预算与持续负载

**【核心结论】**：单请求加载有收益后，还要验证持续正文流量不使队列累积。

**来源**：原文 §13.4、§16.1～§16.5。

## 五、后续演示稿编写约束

### 5.1 页面内容与图示

- 每页只建立一个主要认识，正文采用 3～4 个要点；本大纲中的讲稿展开和出处不全部搬上页面。
- 架构、时序、状态和资源流向页以一幅主图解释关系；对比和验证页使用表格或适量卡片。2×2 卡片适用于真正并列的内容。
- 图内使用中文功能名称，内部类名仅在接口、结构或备查页出现并配释义。箭头注明请求、返回、正文、事件或授权，不能只靠颜色区分。
- 封面统一业务价值与团队信息；封底提供四项实现共识和讨论入口。每页底部统一使用 **【核心结论】**。
- 图题与幻灯片标题避免重复。长表保留检索入口，字段细节进入备注，避免通过缩小字号容纳整章文字。

### 5.2 字体与排版

采用项目开发串讲规范：16:9、纯白底、藏青标题与皇家蓝强调；中文用微软雅黑，代码用 Consolas。封面标题约 26pt，页标题 19～20pt，卡片标题 12pt，正文 11.5pt；段前与段后各 6pt，行距 1.20～1.22。

表格单元格垂直居中，正文 9.2～10pt，内边距 0.02～0.04 英寸。标题控制在页码安全区以内，窄区域精简语句，避免孤字和标点折行。正文过密时先缩减次要文字和调整构图。

### 5.3 数字与证据表达

| 内容类型 | 演示稿中的表达方式 | 典型位置 |
|---|---|---|
| 原需求目标 | 明确标注“需求目标”，说明统计口径和验收前提 | P22、A05 |
| 本版建议 | 标注“设计建议”或“待评审”，不表示已批准 | P04、P08、P23 |
| 条件能力 | 写清启用条件、关闭方式与替代动作 | P10、P12、P18、A01 |
| 算例 | 标注“算例”，保留模型、单位、方向和资源假设 | P19、A05 |
| 实测结果 | 本次材料未提供新增实测；后续加入时绑定包版本、设备、原始数据与对照 | 后续验证页 |

### 5.4 演讲备注与后续制作交付

正式串讲版每页编写 250～400 字备注，按“场景与问题→指图说明→关键边界或失败动作→与下一页衔接”展开，备查页解释读表方式与适用条件。备注是讲解提要，复杂时序页的现场指图时间包含在本大纲建议时长内。

预审版清空全部演讲备注，页面内容与正式版保持一致。章节出处和影响结论的限制保留在页面可读脚注中，便于无备注阅读。外部技术依据沿用原文的官方链接，制作时核对具体引用，不能由在线资料直接推断目标设备能力。

后续实际制作 PPTX 时输出正式串讲版与预审版，通过 PowerPoint COM 导出 1920×1080 预览图并逐页检查标题、图文、表格、底栏及换行。上述步骤属于后续制作规范，本轮不将其报告为已完成。

## 六、编写完成的核对要点

- 24 页主讲与 8 页备查的内容编号完整，时间安排合计 65 分钟，备查不计入主讲。
- 原文第 0～20 章及附录均有入口，新增的生产运行内容在主讲中有独立位置。
- 完整请求中的源持有、目标缓冲、设备可见性和安全回收在不同专题中保持同一含义。
- 目录副本与正文副本、CPU 正文参与与 DDR 正文流量、软件组决定与硬件完成分别表达。
- 需求目标、设计建议、条件能力和算例可辨识，需求映射数量不当作实现完成度。
- 图示、备注和正文之间的细节分工明确；后续制作不需重新发明讲解顺序。
