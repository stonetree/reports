# 统一异构KVCache存储池：项目启动前关键技术原型验证与性能摸底分析报告 (V2)

## 一、 原型验证目标与原则
**目标**：在进入项目全面开发前，通过构建小规模、高针对性的技术原型，对《统一异构KVCache存储池》架构中的核心创新点和高风险技术进行摸底验证。
**原则**：不追求业务全流程闭环（不提前开发全量需求），重点针对**技术创新**与**算法创新**领域中“最不确定”、“对系统底座有颠覆性影响”的最小功能集进行早期排雷，验证新技术能否带来预期的性能突破。

---

## 二、 核心验证候选池（按技术创新与算法创新分类）

结合全盘需求与系统底层痛点，我们将提前验证的最小功能集划分为**技术创新**与**算法创新**两大维度，包含以下 7 项关键技术验证任务：

### 维度一：技术底层创新与硬件能力映射

| 优先级 | 待验证技术任务 | 核心解决问题与创新点 | 验证影响面 |
|:---:|---|---|:---:|
| 1 | **基于 UBMEM 内存语义的全局前缀匹配查表验证** | 替换传统 RPC 查询，利用内存语义实现超低时延的集群级 Prefix 查询与状态维护。 | 决定 TTFT 阶段网络查询的开销底线 |
| 2 | **基于 UBMEM 内存语义的 Block_table 细粒度访问验证** | 区分于前缀表，单独验证将 vLLM 等推理框架底层的物理 Block Table 映射至 UBMEM 的可行性。 | 决定底层内存分配与物理块管理的响应速度 |
| 3 | **多级异构介质间传输通道的技术准备度摸底** | 验证 SSD、DDR、HBM 之间利用直接访问 (Direct Access)、内存语义或 URMA 传输语义进行 KV 搬运的吞吐与延迟。 | 决定集群 KVCache 的物理移动效率与硬件可行性 |
| 4 | **基于 UBMEM/URMA 的组件间控制消息传递重构** | 探索能否用底层内存/传输语义替换各种控制组件之间的传统 RPC/MQ 消息通道。 | 决定系统控制平面的整体并发能力与信令开销 |

### 维度二：算法调度创新与数据结构设计

| 优先级 | 待验证技术任务 | 核心解决问题与创新点 | 验证影响面 |
|:---:|---|---|:---:|
| 5 | **高频读写下全局前缀大表的结构设计与部署探索** | 前缀大表承担查询、位置索引及状态更新，读写极度频繁；验证其 Hash/Tree 数据结构与分片/多副本部署方式对 QPS 的影响。 | 决定元数据平面的 QPS 上限与扩展瓶颈 |
| 6 | **KVCache 智能剔除与升降级决策算法模拟** | 探索淘汰 (Eviction) 和分层升降级 (Promotion/Demotion) 的时机与策略，通过算法仿真寻求最佳复用可用度。 | 决定 KVCache 集群命中率与内外层网络流量大小 |
| 7 | **高并发跨层迁移的一致性控制与租约算法 (Lease/Fence)** | 验证在复杂读写、迁移并行时的 Visibility Fence 与对象租约机制，确保不出现数据幻觉或悬空指针。 | 决定并发数据的正确性与系统长稳底线 |

## 三、 候选验证技术详细分析与验证方案

### 【技术创新方向】

#### 1. 基于 UBMEM 内存语义的全局前缀匹配查表验证
* **分析**：全局 KVCache 前缀表负责请求的 Prefix Hit 匹配、路由以及状态寻找。在现有真实场景中，通常需要走 RPC 协议与远端元数据节点交互，通信开销极大。
* **验证方案**：不挂载真实 KV 数据，仅构建庞大的前缀哈希目录。使用 UBMEM 跨节点直接读取内存地址来匹配 Prefix，验证其与传统 gRPC/Redis 查询的微秒级延迟差异。
* **预期收益**：验证新技术是否能将 TTFT 中的“寻址开销”降低一个数量级。

#### 2. 基于 UBMEM 内存语义的 Block_table 细粒度访问验证
* **分析**：与前缀表（粗粒度、宏观语义）不同，推理框架（如 vLLM）底层的 `block_table` 管理着每一个物理分页的状态与映射，其在推理 Forward 循环中被极高频访问。两者作用完全不同，必须作为独立场景验证。
* **验证方案**：模拟推理引擎的 Paged Attention 过程，通过 UBMEM 远程访问或管理物理 Block 的分配与释放元数据。
* **预期收益**：探索框架内部细粒度调度能否直接受惠于内存语义网络，判断底层解耦的可行性。

#### 3. 多级异构介质间传输通道的技术准备度摸底
* **分析**：底层的 KV 数据流动穿梭于 SSD、本地/远端 DDR、HBM 之间。传统方法依靠 CPU 陷入和普通的 TCP 拷贝。
* **验证方案**：编写最小的 C/C++ benchmark 探针，利用底层驱动，组合验证“远端 SSD -> 远端 DDR -> 目标 HBM”链路。重点测试基于内存语义 (Memory Semantics)、传输语义 (URMA/RDMA) 和 直接存储访问 (GDS) 在大小包混合下的吞吐表现。
* **预期收益**：拿到准确的硬件“能力字典(Capability Matrix)”，指导后续数据面开发的架构选型，避免后期发现某条路径带宽不达标而返工。

#### 4. 基于 UBMEM/URMA 的组件间控制消息传递重构
* **分析**：统一资源池内部，调度器、Directory、Policy Engine 以及远端存储 Worker 之间会产生高频的心跳、QueryPlan 下发、元数据同步等短消息。
* **验证方案**：利用 UBMEM/URMA 搭建一个基础的环形缓冲区 (Ring Buffer) 或消息队列模型，抛弃传统 RPC。
* **预期收益**：如果验证成功，将大幅度降低由于微服务架构带来的 CPU 上下文切换与序列化/反序列化开销。

---

### 【算法创新方向】

#### 5. 高频读写下全局前缀大表的结构设计与部署探索
* **分析**：前缀匹配大表不仅仅是只读的，在 KV 生成、释放、升降级时都会产生状态重写。其数据结构（Radix Tree 还是 分段 Hash）以及部署方式（单点+镜像、全分布式 Sharding 或 P2P DHT）严重影响全局 QPS。
* **验证方案**：通过注入百万级并发并发读写（读写比如 8:2 或 9:1），验证不同数据结构在锁竞争、缓存失效方面的劣势，以及分布式部署下的数据倾斜应对能力。
* **预期收益**：提前选定元数据目录的基础数据结构与分片方案，避免后期集群 QPS 遇到单点瓶颈无法扩展。

#### 6. KVCache 智能剔除与升降级决策算法模拟
* **分析**：决定集群价值的核心不仅是硬件多快，更在于“把正确的 KV 放在正确的层级”。糟糕的升降级策略会导致网络流量风暴，糟糕的剔除算法会导致有效命中率骤降。
* **验证方案**：构建脱机的算法仿真器（Simulator）。输入真实的真实大模型线上请求 trace（包含重复 Prompt、多轮对话特征），比对简单的 LRU 算法与“基于拓扑感知和复用概率预测”的高阶算法在 HBM 命中率和 SSD 读写放大上的差异。
* **预期收益**：以极小的代码开发代价，找到能够极大提高 KV 复用可用度和降低无用流量的策略参数。

#### 7. 高并发跨层迁移的一致性控制与租约算法 (Lease/Fence)
* **分析**：KVCache 在流动过程中，如果前台开始消费，后台正在驱逐，数据极容易损坏。这不仅是工程问题，更是分布式一致性算法问题。
* **验证方案**：实现最小版的 Lease (租约) 与 Refcount 机制模型，通过死循环并发注入“读取-回收-迁移”冲突操作。
* **预期收益**：确保整个存储池不会因为高并发数据流动导致内存泄漏或推理出现脏数据。

## 四、 结论
本次更新充分融入了**控制流元数据分离**（前缀表与 Block Table 差异化验证）、**底层控制通道重构**以及**宏观算法级仿真**等思路。建议项目启动初期的“原型验证小分队”划分为 **硬件基建组（针对技术创新 1-4）** 与 **策略模型组（针对算法创新 5-7）** 双线并行，用 2-3 周的时间快速闭环上述探索，彻底打通整个统一存储池的技术任督二脉。
