# 统一异构KVCache存储池立项汇报页面调整说明

## 一、总体定位

本材料用于项目立项申请与投资决策汇报，不作为立项尽职审查报告。汇报中涉及的性能、容量、正确性和成本指标，应统一表述为项目最终交付目标或建议验收门槛；在原型验证尚未完成前，不得将其表述为当前已经取得的实测成绩。

汇报整体分为两个部分。第一部分用前三页完成投资必要性论证，集中回答项目为什么值得做、为什么应当现在做、为什么需要第一方独立承担，以及相较同类开源软件的长期价值。第二部分通过系统架构、关键技术、复合收益、验证节奏和风险门禁，证明项目已经具备可建设、可验证和可交付的基础。

## 二、前三页核心说服逻辑

### 第一页：从自身责任出发论证立项必要性

本页应围绕“为什么要做、为什么现在做、为什么需要独立建设、为什么应由硬件厂商承担”四个问题展开。论证重点不是增加一个缓存功能，而是建立面向国产硬件的第一方推理基础设施，使高带宽显存、主机内存、固态存储以及UBMEM、URMA等硬件能力，能够通过KVCache全生命周期管理转化为客户可感知的时延、吞吐、容量和成本收益。

### 第二页：以产业趋势强化立项外部依据

本页应选取AMD、NVIDIA、Intel和Arm的官方公开动作，说明头部硬件厂商正在持续增强系统设计、推理运行时、数据移动、内存状态管理和客户交付能力。产业案例用于证明第一方推理基础设施已经成为硬件产业的长期竞争方向，不用于证明本项目已经取得性能优势。对于KVCache，应表述为上述投入在推理状态层的重要收敛点，避免将所有厂商描述为已经交付完整的KVCache全生命周期系统。

### 第三页：与开源软件共生，但第一方责任不可替代

本页不采用静态功能清单或单点性能对抗方式比较Mooncake、LMCache。开源软件持续演进，某项功能是否存在不能构成长期立项依据。比较重点应转向职责中心、独有条件和责任主体：Mooncake的公开能力中心偏高性能传输、对象管理和多路径选择；LMCache的公开能力中心偏推理框架复用、多层缓存和存储扩展。二者的相对边界在于，不会自动为某一目标国产芯片承担跨层优化、跨版本认证、端到端归因、客户结果证明和下一代硬件反向定义。

本项目不主张替代开源软件，也不表述为复用Mooncake或LMCache的数据平面。双方关系应统一描述为接口兼容、标准开放和能力互补，但国产硬件首发适配、跨层修改、生产认证和持续硬件反哺的责任主体必须独立。

## 三、后半部分证据结构

### 系统架构页

本页重点证明系统架构、关键技术和需求追溯已经定义清楚。采用推理框架意图层、KV状态语义层、传输与存储编排层、第一方硬件适配层四层结构，并用访问意图、路径计划、传输描述与可见性约束、实际路径回执构成可对账主链。通过2条系统特性、24条中层需求、149条来源需求和447个实现与验证任务，说明竞争力可以逐项落到需求、接口、探针、门禁和交付物。

### 关键问题与解决路径页

本页不再承担开源方案比较，而是集中解释项目需要解决的核心问题。重点包括物理命中不等于可消费命中、盲目搬运可能形成负收益、多层介质具有不同的成本和故障语义。解决方案采用身份与版本校验、可消费资格判断、收益估算、动作选择、实际路径记录和结果回放，形成从物理命中到正收益命中的完整决策闭环。

### 最终交付价值页

项目价值不应局限于客户界面的运维软件收益，应从客户、生态、能力建设和底层软件孵化四个维度呈现。客户侧关注合格业务事务、时延、吞吐、容量和单位成本；生态侧关注能力档案、硬件能力矩阵、一致性认证和互操作样板；能力侧关注状态语义、路径编排、真实复用率和故障回放；底层软件侧关注将生产瓶颈转化为驱动、固件、芯片和其他软件栈的优化输入。

### 交付目标与验证节奏页

本页应明确区分最终目标与当前状态。采用4至5周原型验证获取关键事实，按基线、硬件能力边界、真实复用上限、混合流量和故障闭环逐步推进；以通过、有条件通过或停止作为阶段门禁，根据证据逐级释放阶段0至阶段3投入。

### 立项决策页

本页应形成明确决策请求，包括原型验证资源与环境、跨团队责任矩阵、公平比较基线及证据包要求。立项建议采用有条件、分阶段方式批准。若关键假设不成立，应允许停止或限定场景，同时保留硬件适配、探针、传输描述、路径记录和一致性认证等可复用资产。

## 四、表达与视觉规范

汇报采用正式、克制的内部立项评审风格，避免技术分享、创业路演或营销海报式表达。页面标题应具有足够识别度但不过度占据画面；正文信息必须能够顺畅推导底部结论，避免内容单薄或结论先行但证据不足。

页面正文以准确中文为主。除KVCache、UBMEM、URMA、TTFT、TPOT以及必要的厂商和产品名称外，不使用项目内部英文对象名和非通用缩写。禁止使用“Best-OSS”等压缩表达，应直接写为“当前最佳可行开源组合”。所有文字必须避免覆盖、粘连、截断和不完整显示。
