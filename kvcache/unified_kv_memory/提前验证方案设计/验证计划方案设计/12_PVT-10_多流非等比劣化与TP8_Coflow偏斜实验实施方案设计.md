## 0. 架构导读与核心概念第一性原理剖析

### 0.1 分布式网络动力学：多流平均值掩盖长尾瓶颈的第一性原理

在分布式存储、大规模 Shuffle 及分布式大模型推理系统中，多个发送端同时向单一接收端口汇聚传输数据时，系统的性能瓶颈往往并不体现在单流的平均带宽，而是取决于突发流量到达的时空聚集度、交换机物理队列的排队动力学以及最慢子流对整体协同任务的拖尾效应。

#### 1. N-to-1 Incast 突发与有限缓冲区排队动力学

- 当 $N$ 个发送节点在极短时间窗口内并发向同一接收网卡推送数据时，汇聚交换机出端口的瞬时入包速率远超出口链路带宽；
- 交换机物理缓冲区瞬间积压，引发 **Buffer Bloat（缓冲区膨胀）**，导致网络排队时延呈非线性陡增；
- 一旦瞬时突发超出缓冲区物理上限，将触发大面积尾部丢包与重传风暴。该物理现象必须通过网卡丢包计数器（Drop Counters）、ECN 标记及交换机 PFC 帧统计进行客观取证，严禁仅凭单次应用层 RTT 猜测。

#### 2. TP=8 Coflow 木桶短板效应

在分布式张量并行 (TP=8) 架构中，大模型每一层的计算均依赖 8 张加速卡上的 KVCache 数据全部就绪。这 8 条相互绑定的子流构成了典型的 **Coflow（协同传输流组）**。该任务的整体完成时间 (CCT) 由最慢的子流（Straggler，慢流/慢节点）严格决定：

$$
\mathrm{CCT} = \max(T_0, T_1, \ldots, T_7)
$$

因此，即使 7 张卡的平均传输时延优化到极低水平，只要有 1 张卡遭遇网络抖动或丢包重传，整体推理计算流水线就会被完全阻塞。优化多卡协同系统必须以压制 CCT 的 P99 尾部时延为唯一度量，严禁使用单流平均时延掩盖协同木桶短板。

### 0.2 大模型推理物理场景映射：首字预计算与 Layer 0 优先级点火

在分布式大模型推理与 PD 分离（Prefill 与 Decode 计算解耦）场景中，KVCache 的网络流转直接决定了端到端性能：

1. **Prefill 阶段**：需要快速回传或加载长 Prompt 的历史 KVCache，直接影响 **TTFT（首字生成延迟）**；
2. **Decode 阶段**：需要持续访问各层 KVCache，直接影响 **TPOT（单字生成延迟）**；
3. **Layer 0 优先级点火机制**：大模型各层计算具有严格的前向依赖关系。如果网络采用无差别的 FIFO（先进先出）队列传输，Layer 0 的数据可能被后续层（如 Layer 31）阻塞在队列尾部，导致 NPU 必须空转等待；若引入 **SemanticQoS** 将 Layer 0 数据映射至硬件最高优先级队列（TC0），则 Layer 0 可以最先到达 NPU 显存，使 NPU 能够**提前启动首层计算**，实现“首层边算、后层边传”的流水掩盖，大幅消除计算气泡。

```text
传统无优先级传输 : Layer 31 ─────┐
                                  ├─► Layer 0 最后到达 ──► NPU 严重空转等待 (计算气泡大)
                   Layer 0  ─────┘

SemanticQoS 调度 : Layer 0  ──► (硬件最高优先级 TC0 极速直达) ──► NPU 立即启动首层计算 (计算气泡消除)
                   Layer 1..31 ─► (流水并发传输，与计算深度重叠掩盖)
```

## 1. 验证目标、交付物与候选准入门槛

### 1.1 核心验证命题

1. **命题一：N-to-1 Incast 呈现非线性尾部放大**。在相同数据块与并发节奏下，随着并发流数 $N$ 增加，P99/P99.9 尾部时延相对于单流基线的放大倍数显著超出线性增长，证实存在排队拥塞风险；
2. **命题二：TP=8 Coflow 完成时间严格受制于最慢子流**。在 8 卡并行协同下，CCT 的 P99 显著偏离单流平均时延，证实单流平均指标无法反映多卡协同真实瓶颈；
3. **命题三：Layer 0 硬件优先级可消除首层等待气泡**。在真实 QoS 队列就绪后，验证 Layer 0 优先直达可降低首层就绪时延，实现计算流水深度重叠。

## 3. 实验动力学模型与核心计算公式

### 3.1 N-to-1 Incast 尾部膨胀模型

设瓶颈链路服务率为 $\mu$，单个流的有效到达率为 $\lambda$，并发流数为 $N$。当并发流数增加导致利用率接近 1 时，有限队列中的等待时间呈非线性增长。每个并发度 $N$ 计算尾部膨胀比：

$$
R_{99}(N) = rac{P_{99}(N)}{P_{99}(1)}, \qquad A_{99}(N) = rac{R_{99}(N)}{N}
$$

当 $A_{99}(N) > 1$ 时，表明该测量点相对于简单线性参考出现了超线性恶化趋势。

### 3.2 TP=8 Coflow 完成时间与偏斜系数

对于第 $j$ 组 TP=8 协同传输任务，8 个 Rank 的完成时间分别为 $T_{j,0}, \ldots, T_{j,7}$：

$$
\mathrm{CCT}_j = \max_{k \in [0,7]} T_{j,k}
$$

该组的单流平均耗时为：

$$
T_{\mathrm{avg},j} = rac{1}{8} \sum_{k=0}^{7} T_{j,k}
$$

Coflow 偏斜系数（衡量木桶短板恶化程度）定义为：

$$
\mathrm{Skew}_j = rac{\mathrm{CCT}_j}{T_{\mathrm{avg},j}}, \qquad \mathrm{Skew}_{\mathrm{P99}} = rac{P_{99}(\mathrm{CCT})}{\mathrm{mean}(T_{j,k})}
$$

### 3.3 Layer 0 计算气泡消除模型

设 Layer 0 的数据完全就绪时间为 $t_{	ext{layer0\_ready}}$，NPU 首层 Attention 算子实际点火计算时间为 $t_{	ext{compute\_start}}$，则首层计算气泡定义为：

$$
T_{	ext{bubble}} = \max\left(0, \; t_{	ext{compute\_start}} - t_{	ext{layer0\_ready}}ight)
$$

- **操作意图**：验证 8 条关联子流必须按最大值对齐的木桶效应，观察合成慢流对整体 CCT 的拖尾影响。
- **执行动作**：分析干净场景与合成扰动场景下的 CCT P50/P99 及偏斜系数 $\mathrm{Skew}$；若某个 Rank 数据缺失，显式置为 `null`。
- **应观察现象**：当 Rank 7 注入 200µs 延迟时，整体 CCT P99 显著恶化，偏斜系数显著攀升。

### 步骤 4：跨节点物理 RoCE 实测与拓扑核验（条件步骤）

- **操作意图**：在真实双节点或多节点网络环境下，采集真实的跨交换机 Incast 排队与硬件丢包。
- **执行动作**：在远端启动独立 Receiver；在 Client 端发起并发传输；同步采集物理交换机出端口丢包与网卡重传。
- **应观察现象**：网卡与交换机硬件计数器记录到真实的排队与重传事件。

### 步骤 5：执行 Layer 0 硬件 QoS 优先级 A/B 实测（条件步骤）

- **前置条件**：已具备物理 RoCE 交换机 QoS 队列与昇腾 NPU 算子事件监听能力。
- **操作意图**：在相同背景流量压制下，对比 FIFO 默认队列与 TC0 硬件优先级队列对首层计算气泡的消除效果。

## 7. 候选准入门槛、判定规则与立即止损机制

### 7.1 候选工程准入门槛一览表

| 核心评估指标 | 候选工程准入门槛 | 权威取证要求 |
|---|---:|---|
| Incast 尾部放大特性 | 高并发下观察到 $R_{99}(N)$ 的超线性增长趋势 | 至少 3 轮独立重复实验与真实样本对账 |
| TP=8 Coflow 偏斜度 | 在 SemanticQoS 调度下 **$\mathrm{Skew}_{\mathrm{P99}} < 1.15$** | 8 个 Rank 完整完成事件与单流对账 |
| Layer 0 首层传输时延 | 开启硬件 QoS 优先级后 Layer 0 传输时延降低 $\ge 50\%$ | 基于硬件 QoS 队列与 NPU 算子事件实测 |
| 首层计算等待气泡 | 开启 SemanticQoS 后首层计算气泡 $T_{	ext{bubble}}$ 大幅削减 | 基于单调高精度时钟精确比对到达与点火时间戳 |

### 7.2 状态判定枚举与规则

- **GO（命题实测证据形成完整闭环）**：在真实硬件网络与多卡协同环境下，Incast 尾部放大、Coflow 偏斜改善及 Layer 0 气泡削减均具备完整 `MEASURED` 证据链；
- **CONDITIONAL（局部场景或特定规模达标）**：仅在 W0/W1 环境下观察到趋势，或缺少部分硬件计数器；结论严格限定于已测条件；
- **NO-GO（协同调度未能取得净收益）**：在真实 A/B 测试中，QoS 调度未能改善 CCT 尾部时延，或引入了更高的网络丢包与 TPOT 恶化；
- **NOT-SUPPORTED（物理环境未支持）**：现场缺乏物理 RoCE 交换机 QoS 配置能力或缺少 NPU 算子事件监听接口；
- **INVALID-EVIDENCE（无效证据）**：使用静态演示数据、将 TCP RTT 冒充 RDMA 硬件排队时间、Rank 样本不全或空字段被当作 0。

### 9.3 常见排错指南

- **执行命令提示缺少 NumPy 模块报错**：当前测试环境未预装 NumPy；应在测试环境中安装标准 NumPy 依赖，并在 Manifest 中记录版本号。
- **提示 `Connection refused` 或端口被占用**：排查本地 18800~18804 或 18900~18907 端口占用情况；确认 Receiver 进程是否已在对应端口正常监听。
- **P99.9 尾部时延波动剧烈**：检查测试有效样本量；当样本数少于 1000 时 P99.9 统计存在统计方差，应增大 `--requests` 参数并增加重复轮次。
- **高并发测试时部分流提前退出**：当前脚本在遇到异常时会终止该流；必须记录失败原因与有效样本数，严禁丢弃失败样本。
- **无法解释网络丢包与重传原因**：应用层 ACK 仅代表应用层握手成功；必须配合物理交换机与网卡计数器对账，未采集到时字段置为 `null`。
- **合成时延扰动参数与代码注释不一致**：以当前源码实际参数（15% 概率、200µs 延迟）为准，并在 Manifest 中如实记录。
- **测试脚本未输出结构化 CSV**：当前受控代码仅在终端打印文本；需由外部解析器将输出转换为结构化 CSV，严禁手工伪造数据。
- **跨节点时钟无法直接对齐相减**：必须记录 PTP 时钟同步方式及误差上限；在缺乏高精度时钟同步时，仅使用单向 RTT 或将跨节点差值标记为无效。
