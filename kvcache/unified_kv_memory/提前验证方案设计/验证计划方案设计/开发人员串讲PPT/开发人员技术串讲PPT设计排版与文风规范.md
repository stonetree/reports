## 一、文风基调与表达方式规范 (Tone & Engineering Text Style)

面向一线研发与架构技术人员时，语言必须坚持**务实朴实、平实直白、数据驱动、严谨落地**为主，彻底杜绝行政化套话、公关宣传口号与过度渲染的修饰词。

### 2. 专有英文术语首次出现释义规范
- 任何技术缩写或专有名词在幻灯片或讲稿中首次出现时，必须在括号内附加一句话**直白功能释义**：

  - *例*：`Saved-Prefill（首字生成预计算节省：利用已缓存 KV Cache 避免重复计算 Prompt，显著降低首字时延 TTFT）`
  - *例*：`UBMEM（统一总线内存直通共享协议：支持跨节点与异构设备间直接共享内存地址空间的底层协议）`
  - *例*：`URMA（通用远程直接内存访问：用户态高性能 RDMA 驱动接口与通信协议）`
  - *例*：`Direct-View（远端直读：直接通过高速总线跨节点读取远端显存中的 KV 数据，不产生本地显存拷贝）`

  - *例*：`SemanticQoS（前后台服务质量保障策略：通过网络优先级队列映射与微秒级退避保障前台在线推理 TPOT）`

### 容器微圆角规范 (Enterprise Micro-Radius)
- **杜绝过大圆形倒角**：过大的倒角会让严肃的系统架构评审文稿显得不正式、非工程化；
- **微圆角比率标准**：
  - 容器卡片统一采用 **0.02 微圆角**（~2.3mm 微弧，`shape.adjustments[0] = 0.02`）；
  - 底部【核心结论】高亮横条采用 **0.025**；
  - 页面右上角页码徽章采用 **0.05**；
  - 既彻底消除直角的生硬毛刺感，又保证工程级严谨工整的视觉质感。

## 三、排版体系与字号间距规范 (Typography & Spacing Matrix)

### 1. 字体体系
- **中文字体**：`Microsoft YaHei`（微软雅黑）。
- **英文字体/代码/参数/协议名**：`Consolas`（或 `Microsoft YaHei` 混排）。

### 2. 页面与卡片通用层级字号（大屏演示友好标准）
- **封面大标题 (Cover Title)**：`26pt Bold`（皇家藏蓝 `#1E3A8A`）；
- **页面主标题 (Slide Header Title)**：`19pt ~ 20pt Bold`（皇家藏蓝 `#1E3A8A`，字符宽度必须留出右侧安全边界，严禁向右延展与页码徽章重叠）；
- **页面副标题 (Slide Subtitle)**：`11pt ~ 12pt Regular`（石板灰 `#475569`）；
- **页码角标 (Page Badge)**：`11.5pt Bold`（经典蓝 `#2563EB`，右上对齐，格式如 `第 05 / 16 页`）；
- **卡片 Header 标题**：`10.5pt ~ 12pt Bold`（白色文字，强制设置 `word_wrap = False` 杜绝多行挤压折断）；
- **卡片 Header Tag 标签**：`9.5pt ~ 10pt Bold`（浅蓝 `#BFDBFE`，格式如 `[阶段目标]`、`[工程责任边界]`）；
- **卡片主标题（无 Header 卡片）**：`15.5pt ~ 16.5pt Bold`；
- **卡片二级模块标题（`【...】`）**：`11.5pt ~ 12.5pt Bold`，配置显式段前（`Pt(3.5~6)`）与段后（`Pt(1.5~4)`）间距；
- **卡片正文文字**：全面提升至 **`11.0pt ~ 12.5pt`**（普通大卡与 2x2 卡 `11.5pt ~ 12.5pt`，标准卡绝不低于 `11.0pt`；多列极密卡片按阶梯采用 `9.2pt ~ 10.2pt`；右侧极密拆解卡最低 `8.8pt`，严禁无故缩至 7~8pt 导致无法辨识）；
- **表格单元格正文**：`10.5pt ~ 11.0pt`（表头 11.0pt Bold），全量单元格必须强制设置 `cell.vertical_anchor = MSO_ANCHOR.MIDDLE` 垂直居中，边距紧凑；
- **底部核心结论横条 (Takeaway Banner)**：
  - 结论标头：`【核心结论】` `12pt ~ 13pt Bold`（经典蓝 `#2563EB`）；
  - 第一行系统事实：`11.5pt ~ 13.0pt Bold`（深灰 `#1E293B`）；
  - 第二行核心指标与承诺：`11.5pt ~ 13.0pt Bold`，核心数据用**鲜红加粗 (`#DC2626`)** 突出。

### 3. 多容器动态字号与间距阶梯矩阵 (Dynamic Scale Matrix)

在多列网格与复合卡片中，**严禁一刀切使用固定字号**。必须依据卡片物理宽度（Inches）与信息承载密度匹配相应的字号、段落间距与行距阶梯：

| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **标准 2 栏 / 2×2 卡片** | `6.05"` | **`11.5 ~ 12.5pt`** | `12.0pt Bold` | `5.5 ~ 7.0pt` | `1.22 ~ 1.28` | 设计范围、原则界定、PVT 验证方案页 |
| **下半部并排双宽卡** | `6.05"` | **`9.8 ~ 10.5pt`** | `10.5pt Bold` | `3.5 ~ 4.5pt` | `1.18 ~ 1.22` | 高并发瓶颈防线、资产清单、落地承诺 |

| **4 列标准宽度卡片** | `2.90"` | **`9.8 ~ 10.5pt`** | `10.5pt Bold` | `4.5 ~ 6.0pt` | `1.18 ~ 1.22` | 元数据组织、阶段门禁、立项共识 |

### 4. 舒展行间距与显式段落解耦机制 (Spaced Line & Paragraph Decoupling)
1. **调大行间距消除文字压抑感**：
   - 全面摒弃默认单倍行距或过于紧凑的行高，将段落行间距整体设定为 **`1.20 ~ 1.28`**（高密卡片不低于 `1.16`），保证字符上下拥有充裕的呼吸空间；
2. **显式段落解耦（消除多 Bullet 黏连）**：
   - **严禁用 `\n` 简单拼接长字符串来排布多个要点**；
   - 每一个列表项、要点必须拆分为独立的 Paragraph 对象，分别配置 `space_before` 与 `space_after`，赋予要点之间明确的结构化间距；
3. **文本对齐方式按语义选用**：
   - 架构子卡片与关键状态标签文字推荐采用**居中对齐** (`PP_ALIGN.CENTER`)，增强视觉对称感；
   - 正文列表与分析叙述采用左对齐，适度扩写深度工程分析，杜绝文本框大面积空白留白。

## 四、六大经典幻灯片版式模型 (Layout Grid Models)

全套 16:9 画布尺寸基准：宽度 `13.333"` 英寸，高度 `7.50"` 英寸。顶部统一预留 `1.18"` 高度给主副标题栏，底部 `6.40"` 统一配置全宽核心结论横条。

### 破除“千篇一律的左图右文”审美疲劳与图文冗余消除机制
- **摒弃单一机械套路**：坚决杜绝每一页都机械使用“左边框架图 + 右边文本框”的模板化排版；
- **图文冗余消除机制**：在审查发现右侧文本框内容与左侧架构图基本重合时，**坚决去掉右侧文本框**，将左侧架构图宽度自适应调整为大图（`8.20"`）或全宽图（`12.333"`），并将文本框中的文字与关键工程分析深度融入重绘后的架构图中；
- **上下分区差异化排布**：类似 Slide 6/7/8 这种上下两个部分内容实际上有分区的排布，上下两个部分可以用不同的排布，包括不同的字体大小、不同的段落间距与行高，不能机械一刀切保持全页所有卡片字体一样大。

## 五、换行保护、防孤字与标点避头尾铁律 (Anti-Orphan & Punctuation Rules)

在评审演示文稿的视觉走查中，**标点单独折行与单字孤立成行属于一票否决的排版硬伤**。必须在代码编写和文本精雕阶段严格执行以下铁律：

1. **严禁行首孤立标点（标点避头律）**：
   - 中文逗号（`，`）、顿号（`、`）、句号（`。`）、分号（`；`）、冒号（`：`）严禁折行到新一行的起始位置；
   - *成因*：文本长度恰好使上一行排满汉字，排版引擎将紧随其后的标点符号推至下一行首；
   - *消除手段*：对上一行文字精简 1~2 个汉字，使标点稳妥留在上一行行末；或将该句提前断句。
2. **严禁单字孤立成行 (Anti-Orphan Characters)**：
   - 换行后在新的一行中**严禁仅出现一个或两个汉字**（例如独占一行的“迟”、“率”、“径”、“达”、“发”、“重算”、“运行”）；
   - *消除手段*：精炼句子前文，或将整句拆分为两行均衡对齐，确保第二行至少容纳 4~6 个汉字。
3. **严禁孤立数值/符号脱节折行 (Anti-Orphan Tokens)**：
   - 百分比数值（如 `3%`、`10%`、`≥ 20%`）、时延指标（如 `< 500µs`）严禁与前面的被修饰词（如 `前台 TPOT 干扰率`、`SIGBUS 跳出`）脱节并单独换行。
4. **严禁专业英文缩写与编号中途截断**：
   - 连续编号（如 `SR23-01-21~29`）、英文方法名（如 `Worker.step()`）严禁在连字符或圆点处被强行打断到新行；
   - *消除手段*：调整表述结构，例如改为 `承接 L3 传输层 9 条 SR (SR23-01-21~29)`。
5. **底部【核心结论】横条双行精算饱和度**：
   - 底部横条必须采用显式换行符 `\n` 分为纯净的 2 行，严禁自然溢出折成 3 行；
   - 第一行字数控制在 **48 ~ 56 字**，第二行字数控制在 **48 ~ 56 字**，保证文字两端饱满均衡且两侧留有充足呼吸边距。
6. **防标题重叠**：
   - 页面左上角 19pt Bold 主标题字数必须控制在安全宽度内，严禁向右延展与右上角 `第 XX / XX 页` 页码徽章发生物理重叠。

## 六、结构化富文本 Runs 高亮实现方案

为了在统一的列表项中灵活实现局部文字加粗与重点色彩高亮（如红色指标、藏蓝术语），底层通用组件必须支持 `runs` 字段：

```python
# 列表项多属性 Run 定义结构
item = {
    "lead": "直通路机制：",
    "runs": [
        ("硬件 DMA 直达显存，", False, None),
        ("严格绕过主机内存 (Payload Bypass DDR)", True, RED_HIGHLIGHT),
        ("，", False, None),
        ("Host CPU 严格零数据拷贝", True, RED_HIGHLIGHT),
        ("。", False, None)
    ]
}
```

**渲染机制要点**：
- `lead`（引导词）：加粗，颜色采用卡片 Header 对应的主题色或藏蓝色，末尾带中文冒号；
- 遍历 `runs` 元组：`(text, is_bold, color)`，根据元组属性动态为 `run` 设定 `font.bold` 与 `font.color.rgb`；
- **防折行处理**：紧随重点短语后的中文标点必须与前面短语合并或作为独立 run 严格校验，防止标点被推到下一行首。
