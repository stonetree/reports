# 需求追溯与验收覆盖矩阵

## 1. 追溯规则

本矩阵按以下链路审查：

```text
第一方责任/竞争力假设
  → PVT/CVT 决策问题与 E0～E3 证据门
    → IR 技术锚点
      → SR23 独立交付实体
        → SRS 正式需求/工程门禁
          → 原始证据、结论、正式项目延续资产
```

原型不能以“关联某个 IR”替代逐项交付证据。每个 Go/Conditional 结论必须指出将进入哪个 SR 的接口、代码、Provider、工具或测试；No-Go/Not Supported 必须指出关闭哪个 feature flag、使用什么回退，以及影响哪些 IR/SR。

## 5. 跨项证据复用与禁止循环

| 生产项 | 消费项 | 复用内容 | 防循环规则 |
|---|---|---|---|
| PVT-00 | PVT-02～07 | workload、recompute、trace、指标分母 | PVT-00 最终 E0 可在 PVT-01 成本完成后补算，但不改原始 Trace |
| PVT-01 | PVT-02～05/07、CVT-03 | Capability、路径成本、Provider、Receipt | PVT-04/05 不得用自己优化后的端到端结果反推 PVT-01 峰值 |
| PVT-02 | PVT-07、CVT-01 | Descriptor/DAG/Cancel | 编译基线固定，不因 PVT-07 最优对象挑选而重定义 |
| PVT-03 | PVT-04/05/07、CVT-02 | View/Copy 白名单、Lease/Revoke | 不允许 QueryPlan 绕过 Guard 扩大 Direct View |
| PVT-04 | PVT-05/07 | Cost/Plan/Reason/Fallback | Oracle 只用于离线评估，不进入在线输入 |
| PVT-05 | PVT-07、CVT-02 | DDR Role、水位、迁移/容量包络 | CVT-02 只改变迁移后端，不改容量口径 |
| PVT-06 | PVT-07、CVT-01/02 | Eligibility/Attach/Rank/Fault | 所有高级路径仍必须通过同一 Eligibility |

## 7. 源文档口径校准

- 正式统计采用 2 SF、24 IR、144 正式 SRS、5 工程建议、38 SR、203 AR；竞争力讲稿中的旧版“447 个实现与验证任务”不用于本设计的工程分母。
- V1.6 原型清单是 8 PVT + 3 CVT；定量模型的 `PVT-08` 在本设计中对应 CVT-01，不新增第 9 个必做项。
- 线速/设备峰值正式门槛为 ≥80%；定量模型的 90%/95% 是 stretch 或特定硬件向量。
- Direct View Revoke 正式门槛为 P99 <1ms；更严的微秒级目标可记录但不覆盖 V1.6。
- 所有优势均为待判定；工作簿结构 PASS 不代表硬件、性能、客户价值或壁垒已成立。
