    - 开源方案：基于静态 Cache Hit / Prefix 匹配，缺乏针对加载与重算代价（load-vs-recompute）的动态仲裁。
    - 本项目：**意图驱动与前递预取** —— 以 `KVAccessIntent` 为决策要素，综合带宽、队列与 FLOPs 动态权衡加载、远程 View、前递与重算代价，主动拒绝负收益加载，P99 尾时延降低 ≥20%。

- **二、 与 NVIDIA 整套方案 (Dynamo / KVBM / NIXL) 的战略对标与第一方责任**

- **8 大 PVT 验证清单**：
  - `PVT-00`: 业务负载 saved-prefill 价值 ── Saved-prefill 节省时间 > 控制+传输+Attach 开销 (退场：若无复用价值，收缩为白名单场景)

  - `PVT-03`: Direct View 真实安全区 ── 元数据 View 延迟 < 10μs，无跨节点写冲突 (退场：禁用 View，强制 Copy-to-HBM)

  - `PVT-07`: 局部收益转化为在线净收益 ── 混流下 TTFT P99 降低 ≥20%，TPOT 无恶化 (退场：触发项目级 No-Go 或缩项)

## 幻灯片 10/10：风险评估与 No-Go 退场预案 —— 风险可知可控与资产保留

- **立项论证要点**：全面识别 10 大潜在研发与业务风险，确立硬性 No-Go 止损触发条件，确保失败时可安全收缩并沉淀高质量资产。
- **一、 10 大关键风险与管控措施**
  - `开源快速追平`: 聚焦第一方 Day-0 交付、微架构协同与硬件联合设计闭环。
  - `真实复用不足`: PVT-00 先测上限，若 Saved-prefill < 10% 自动收缩为特定白名单场景。
  - `数据获取困难`: 采用“公开数据集+脱敏 Trace+合成轨迹”起步，仅采集元数据与统计指标。
  - `硬件合作滞后`: 立项时冻结跨团队 RACI，设立专用接口人与周度问题升级通道。
  - `决策开销抵消`: 采用 Lightweight C++ 引擎，控制路径决策耗时 < 50μs。
  - `TPOT 尾部抖动`: 贯彻 Ready 屏障与并发抢占隔离，限制单次 IO 粒度。
  - `内存静默损坏`: 强制开启网卡与总线硬件 CRC 校验，随路带回 Checksum 校验和。
  - `生态标准孤立`: 提供面向 vLLM / SGLang / Mooncake 的开源适配 Connector。
  - `团队经验瓶颈`: 建设工具化 Trace Harness 与自动化 Fault-Injection 故障注入回归套件。
  - `范围蔓延风险`: 严格限定范围：只处理与 KVCache 推理状态相关的关键数据。
- **二、 No-Go 止损触发与 5 大安全收缩资产保留方案**
  - **止损触发机制**：若 PVT-07 混流测试未能降低 TTFT P99，或无法获得硬件联合修改权，触发 No-Go 止损。
  - `资产保留 1：UBMEM/URMA 驱动`: 转为开源 Mooncake 的高性能 Provider 插件。
  - `资产保留 2：描述符编译器`: 转为底层硬件通用 Scatter-Gather 描述符编译库。
  - `资产保留 3：测试套件`: 转为国产芯片 KVCache 标准化 Conformance 测试包。
  - `资产保留 4：决策日志与轨迹`: 转为推理工作负载性能分析与画像工具。
  - `资产保留 5：硬件需求分析`: 输出为下一代国产芯片微架构修改建议书。
