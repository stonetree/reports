# 统一异构 KVCache 存储池关键技术与竞争力

> 文档状态：阶段性讨论稿  
> 当前范围：已讨论清楚的项目定位、关键技术与竞争力表述  
> 后续议题：一页竞争力汇报 PPT 左侧软件栈图的内容与构图

## 一、项目总体定位

本项目不是在既有硬件能力之上进行简单的软件适配，而是以真实业务收益牵引软硬协同设计，以 URMA 承担大块数据流动、以 UBMEM 构建共享内存与元数据快路径，再通过 QueryPlan 和统一 KV 对象将底层能力转化为可决策、可执行、可持续优化的统一内存池。

项目面向 RAG、智能体、长上下文以及输入预计算/逐词生成分离等推理场景，贯通 KVCache 的传输、匹配、复用和管理全链路，将分散在不同框架、节点和异构介质中的 KVCache 转化为可统一管理、跨域复用的集群级资源。

## 二、关键业务竞争力

- 减少公共前缀、多轮会话和输入预计算/逐词生成分离场景中的重复 Prefill，将 KVCache 复用稳定转化为首 token 时延收益。
- 打破单一框架、单一节点和单一介质的缓存边界，形成跨框架、跨实例、跨节点的集群级 KVCache 复用能力。
- 统筹 HBM、DDR、SSD 及远端资源的容量与性能分工，持续扩展可服务 KVCache 容量并提升异构资源利用效率。
- 以真实业务收益定义软硬协同方向，以软件策略组织硬件能力，以硬件状态驱动动态决策，共同构筑统一异构 KVCache 内存池。

## 三、关键技术与技术竞争力

### 1. 有机融合 URMA 与 UBMEM 关键特性，协同承载大块 KVCache 传输与高频元数据同步，构建跨设备、跨节点的 KVCache 高性能数据底座

- **以 URMA 承载大块 KVCache 正文的批量异步传输，释放跨节点互联带宽，压缩远程数据搬运的时延与 Host 开销。**
- **以 UBMEM 内存语义承载前缀目录、对象位置和就绪状态等高频元数据访问，缩短集群状态同步与查询决策链路。**
- **通过软硬协同，由 UBMEM 元数据变化驱动 URMA 数据传输，使对象发现、路径决策、数据到达与安全消费形成连续闭环。**

### 2. 构建跨框架统一的 KVCache 前缀索引与消费资格判定体系，贯通候选发现、对象定位和状态校验链路，提升集群级匹配效率与命中质量

- **基于 UBMEM 共享地址空间重构全局前缀匹配表，将 vLLM 块哈希与 SGLang 前缀树纳入集群共享索引，减少跨节点目录复制与远程查询开销。**
- **利用 UBMEM 远端 Load/Store、原子操作、部分缓存一致性和事件通知改造 block_table，使块地址、对象位置与就绪状态变化能够被低时延感知。**
- **在 CPU 侧利用 SIMD 加速块哈希计算，通过软硬协同衔接 UBMEM 全局匹配与消费资格校验，形成“本地高速计算、全局低时延匹配”的查询快路径。**

### 3. 建立以真实业务正收益为依据的 KVCache 载入—重算决策与多副本选路策略，优化 KVCache 流动的路径与时机，将缓存命中稳定转化为首 token 时延收益

- **将链路带宽、传输时延、队列负载、拓扑距离、UBMEM 访问成本和设备拥塞状态转化为 QueryPlan 决策参数，使底层硬件状态直接参与载入—重算判断。**
- **通过软硬协同，将 QueryPlan 决策编译为传输路径、任务粒度、URMA 描述符、队列优先级和执行时机，使业务收益判断直接约束底层数据流动。**
- **持续对账预测成本与实际 TTFT、TPOT 和资源消耗，以可观测、可决策、可控制为原则牵引硬件接口演进，形成软硬协同的业务性能优化闭环。**

### 4. 构建面向全局资源效率的统一 KV 对象与图式分层管理体系，重塑 HBM、DDR 和 SSD 的容量分工与数据流动方式，持续扩展可服务容量并释放异构资源价值

- **利用 UBMEM 共享地址空间与 KVObject 统一对象模型，建立跨 HBM、DDR 和远端内存的一致资源视图，并通过 Extent 映射衔接 SSD 容量空间。**
- **根据 URMA、UBMEM 和 SSD 不同的数据访问特征设计 KVCache 数据结构与传输粒度，使高频元数据、小粒度活跃数据和大块冷数据分别匹配最合适的访问方式。**
- **以业务收益为门槛推进软硬协同设计，按需调用或牵引 DMA、C2C、页迁移、原子重映射和硬件 QoS 等底层原语，将分层迁移与容量治理策略转化为可直接执行的硬件动作。**

## 四、竞争力总结

本项目的核心竞争力，不是单点传输、缓存索引或介质分层能力，而是形成了一条由业务收益牵引的软硬协同技术链：

1. UBMEM 提供统一地址空间和高频元数据快路径，支撑集群级 KVCache 发现、匹配和状态协同。
2. URMA 提供大块 KVCache 正文的高性能传输路径，将跨设备、跨节点的数据移动效率转化为推理性能基础。
3. QueryPlan 将实时硬件状态、复用收益和业务时限统一到载入—重算决策中，决定 KVCache 是否流动、从哪里流动以及何时流动。
4. 统一 KV 对象与图式分层管理将软件策略转化为底层硬件动作，持续优化 HBM、DDR、SSD 及远端资源的全局使用效率。

由此形成“业务收益定义目标、软件策略组织路径、硬件能力执行动作、运行数据反馈决策”的闭环，共同构筑统一异构 KVCache 内存池。
