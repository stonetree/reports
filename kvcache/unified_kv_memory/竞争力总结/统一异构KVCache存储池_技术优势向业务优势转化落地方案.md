### 3.1 Step 1: 业务场景精准分层匹配

1. **场景 A：高频 Agent 智能体 / 多轮对话 / RAG 搜索增强系统**  
   - *痛点*：用户每发送一条消息，系统均需对数万 Token 的历史对话重新做 Prefill 计算，TTFT 动辄 2~5 秒，用户体验极差。  
   - *落地抓手*：主打 **UBMEM 微秒级感知 + URMA 极速换入**。将历史对话前缀瞬间复用，TTFT 压缩至 200ms 以内，支持 Agent 的高并发爆发。
2. **场景 B：128K~1M 超长上下文法律/金融/代码大模型分析**  
   - *痛点*：HBM 显存瞬间爆满（OOM），导致系统频繁拒绝服务（429 Too Many Requests），硬件扩容成本极高。  
   - *落地抓手*：主打 **HBM↔SSD Direct PCIe DMA 容量主路径**。利用便宜的 NVMe SSD 作为存储池，单节点可服务的超长文本并发数提升 3 倍，TCO 降低 35%+。
3. **场景 C：多租户 API 开放平台 (Cloud LLM API Gateway)**  
   - *痛点*：多租户并发混压时，后台换入 KV 导致前台生成严重卡顿，且存在跨租户数据泄露隐患。  
   - *落地抓手*：主打 **双 Stream 物理流水重叠 + `AttachHandle` 金融级租约**。保障生成流 P99 TPOT 抖动 $< 3\%$，确保数据绝对安全。

### 3.2 Step 2: 财务与商业 TCO 对账模型

在向 CTO、CFO 及业务负责人汇报时，统一使用以下财务量化公式：

$$\text{TCO}_{\text{QualifiedRequest}} = \frac{\text{Capex}_{\text{ServerHost}} + \text{Capex}_{\text{NPU}} + \text{Opex}_{\text{Power\&Cooling}}}{\text{Total Qualified Served Requests}}$$

1. **硬件 Capex 节约**：主路径实现 `Host Payload Touch Budget = 0` 后，服务器节点无须配备高端双路 CPU 与海量 DDR 内存，单服务器硬件 Cost 压减 **30%~40%**。
2. **算力 Opex 节约**：凭借 `QueryPlan` 动态决策，Saved-Prefill 节省了大量 NPU 前向矩阵计算力，NPU 卡时与电费直接压减 **25%+**。
3. **综合成果**：单位合格请求综合成本降低 **$\ge 35\%$**。

### 3.3 Step 3: 原型验证 (PVT-00~07) 证据链闭环

为了确保技术优势不悬空，项目建立了以 **PVT-00 ~ PVT-07 为代表的证据链**：
- **PVT-00**：出具真实业务流量下的 Saved-Prefill 收益上限评估报告；
- **PVT-01**：在真实压测下证明 `Host Payload Touch Budget = 0` 且丢包率/CPU 占用为 0；

- **PVT-07**：证明前后台混压下 $P_{99}$ TPOT 干扰严格小于 3%。
