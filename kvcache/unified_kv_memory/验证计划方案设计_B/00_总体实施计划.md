# 统一异构 KVCache 存储池原型验证总体实施计划

## 1. 决策目标与成功定义

本计划用 4～5 周购买四类事实：

1. E0 立项充分性：目标流量是否存在足够自然复用及 Saved-Prefill 上限；
2. E1 能力路径：热路径、容量路径、布局编译和可消费正确性是否真实成立；
3. E2 决策优越性：View/Load/Move/Recompute、路径和分层策略是否优于静态规则；
4. E3 系统净收益：在公平基线和真实混压下是否提升 SLO 合格业务事务并降低单位成本。

总体 Go 不是“11 项全部达到最好数字”，而是 8 个必做项形成无正确性缺口、可回退、可解释的 E0～E3 链路；任何核心假设不成立时，能按预设门槛缩项、换路径或停止，而不是继续堆功能。

## 2. 不变量与边界

### 2.1 技术不变量

- 语义先于位置：Raw Hit 只有通过身份、版本、布局、Ready、Lease、Rank、安全域和时限检查后才可能成为 Usable Hit。
- 价值先于容量：只有 `SavedRecompute > Lookup + Load + Attach + Sync + Interference` 才允许消费已有 KV。
- Recompute 是一等路径：远端加载、Direct View 或迁移为负收益时主动重算。
- Ready 先于消费：Completion、Fence、Visibility、Integrity、Version 和 Lease 未闭环，不得返回 AttachHandle。
- 实际路径先于宣称路径：任何直达、低 Host 参与或零拷贝主张必须由 ActualPathReceipt 和 Host Touch 计数证明。
- 开放数据平面、自控状态语义：兼容 vLLM/SGLang 和可用的 Mooncake/LMCache Provider，但 QueryPlan、消费资格、证据和目标硬件认证由本项目负责。

### 2.2 明确不在立项前完成

- 生产级目录 HA、全网调度、完整 TierManager、生产 QoS 控制器、在线学习和自动扩缩容；
- 所有模型、后端、硬件平台和多租户计费；
- 以 CPU 软件压缩/解压、CPU 全量 CRC 或隐式 DDR staging 修补主路径；
- 无触发证据的多播、Atomic Remap、DPU/Codec 探索；
- 把合成热点、单次截图、峰值带宽或手工 Excel 当作生产收益证据。

## 5. 环境设计

### 5.1 目标环境

建议以 2 台 8 卡目标 NPU/GPU 服务器为主环境，每节点具备代表性 HBM、主机 DDR、目标 UBMEM/URMA 或 RDMA/C2C 通路、至少一组 NVMe SSD；若实际硬件拓扑不同，必须在 `EnvironmentManifest` 中记录，并将不具备的路径标记为 `NOT_SUPPORTED`，不得用模拟结果冒充物理路径结论。

最小拓扑：

- 节点 A：Prefill/Source、远端 KV 副本、SSD/DDR/UBMEM 源；
- 节点 B：Decode/Target、目标 HBM、Attach 消费端；
- 管理节点或隔离 CPU 核：Trace、指标收集、故障控制，避免和数据面争抢；
- 同节点校准路径：HBM↔DDR、HBM↔SSD；跨节点路径：HBM/DDR↔HBM/DDR；
- 网络/SSD 限速器：支持可重复的延迟、丢包、带宽、QD、IOPS 和故障注入。

### 5.2 软件与版本冻结

每次基线冻结至少包含：OS/kernel、驱动、固件、NPU/GPU runtime、NIC/DPU/SSD firmware、文件系统/Direct I/O、vLLM、SGLang、Mooncake/LMCache（若可用）、模型权重、tokenizer、chat template、量化格式、TP/PP、调度参数、内存水位和所有 feature flag。

框架及开源组合必须在同硬件、同模型、同 SLO、同工作负载、同统计窗口和同等调优预算下比较。任何只在一方开启的量化、并行、批量或缓存开关都必须写入差异说明。

### 5.3 工作负载

- 真实脱敏 Trace：优先 1～3 天代表业务，分租户/模板/场景分层；
- 替代双轨：固定版本 ShareGPT + Zipf/Poisson 合成轨迹；合成热点不得外推生产；
- 上下文：4K、32K、128K、256K+；容量专项增加 1M；
- 并发：1～128，逐项按清单裁剪；
- 工作负载族：共享前缀、长上下文 Agent/RAG、长尾低复用、突发流量、前后台混压；
- KV 规格：MHA/GQA 与 MLA 分开报告。定量模型中的 TP=8、FP8、70B/405B/DeepSeek MLA 仅作容量和链路压力测试向量，实际模型参数必须由 `KVBlockSpec` 实算。

## 7. 统一进入与退出条件

### 7.1 Definition of Ready

实验只有在以下条件全部满足后才能计入正式证据：

- ExperimentManifest、环境版本、硬件拓扑和 feature flags 已提交并校验；
- 基线已在同一环境运行，核心指标重复实验 CV 满足要求或有已批准解释；
- 统一时钟误差、监控开销和压测端瓶颈已校准；
- case 的期望路径、允许回退、禁止路径和 Host Touch 预算已声明；
- 故障注入有回收/恢复方案，不会污染后续 case；
- 输出目录可写，原始数据不会被汇总脚本覆盖。

### 7.2 Definition of Done

- 主矩阵、故障矩阵和公平基线完成，至少 3 次独立重复；
- 原始样本、分位数、95% 置信区间、CV、资源计数和失败样本齐全；
- Planned Path 与 ActualPathReceipt 一致或差异已解释；Host Touch 可对账；
- 所有异常有标准 reason code，Fallback 行为与预期一致；
- 给出 Go / Conditional / No-Go / Not Supported、适用边界和默认回退；
- 回写对 IR、SR23、SRS、架构、范围、采购、人力和竞争力主张的影响；
- 可延续代码、接口、golden/fault cases、探针和回放器有提交位置及 Owner。

## 8. 项目级判定逻辑

### 8.1 Go

PVT-00 证明至少一个明确业务分层有可兑现上限；PVT-01～06 形成无错误消费、可回退的路径/语义/决策闭环；PVT-07 在公平基线下达到 E3 门槛，且收益不是由弱基线或不可公开微架构信息单独造成。批准冻结范围进入 P0。

### 8.2 Conditional

核心闭环只在限定模型、框架、上下文、拓扑或介质水位成立。必须冻结白名单、feature flag、回退、监控告警、补证计划和对外不可外推边界；采购与人力只覆盖白名单。

### 8.3 No-Go

自然复用不足、无真实容量主路径、错误消费、决策持续负收益或 E3 系统收益为负。停止对应主路径，调整架构/范围/采购/人力；保留 Provider、Descriptor Compiler、Trace Harness、Conformance/Fault Suite 等可复用资产。

### 8.4 Not Supported

当前平台无所需硬件/驱动/固件能力，或计数器无法证明路径。写入支持矩阵，提供显式替代路径或重算；不得用 CPU/DDR 隐式填补并继续宣称直达。

## 9. 主要风险与处置

| 风险 | 早期信号 | 处置 |
|---|---|---|
| 真实 Trace 不可得 | D0 无数据授权 | 启用固定 ShareGPT+Zipf 双轨，结论降级为 Conditional，禁止生产外推 |
| 目标硬件未就绪 | Provider/固件/计数器缺失 | 使用桩件验证接口，物理能力标 Not Supported；不把模拟结果计入 E1 |
| 压测端成为瓶颈 | 负载机 CPU/网络满载 | 多负载机、预生成请求、隔离 CPU、以服务端接收率复核 |
| 时钟不可比 | 跨节点时延出现负值/漂移 | PTP/单调时钟校准；端到端与单端时间分开；不使用未校准跨机时间 |
| 基线调优不公平 | 一方使用默认配置 | 记录调优预算与尝试；由独立评审签署公平性 |
| 指标采集干扰 | 开关监控后 TPOT 变化≥1% | 降采样、Thread-local/硬件 counter；观测开销单独扣除并报告 |
| 多项共享环境相互污染 | case 后性能漂移 | 每 case 清理缓存/队列/故障状态；环境指纹不一致即作废 |
| 门槛冲突 | 不同材料数字不一致 | 采用 README 的事实优先级；较严数字作为 stretch，不替代 V1.6 判定 |
