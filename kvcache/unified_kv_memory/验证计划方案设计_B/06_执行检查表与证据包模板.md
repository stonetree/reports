# 执行检查表与证据包模板

## 1. 启动评审检查表

### 1.1 范围与决策

- [ ] `validation_id`、证据门和要改变的决策唯一明确；
- [ ] 假设、Go/Conditional/No-Go/Not Supported 与默认回退已预注册；
- [ ] 明确范围内、范围外和不做项；
- [ ] 主/次 IR、SR23、SRS 锚点与正式项目延续资产已填写；
- [ ] CVT 有触发证据和批准记录；PVT 不被拆成互不共享的额外项目。

### 1.2 公平基线

- [ ] 模型、权重、tokenizer、template、dtype、TP/PP 相同；
- [ ] 框架、硬件、拓扑、驱动/固件和统计窗口冻结；
- [ ] prompt/workload、并发、到达分布、输出 token、SLO 相同；
- [ ] 原生框架和当前最佳可行开源组合已配置；
- [ ] 调优预算、尝试和差异有记录；
- [ ] 必要的简单基线、State Intelligence Off 和 Microarchitecture Info Removed 已纳入。

### 1.3 环境与证据

- [ ] EnvironmentManifest 和摘要生成；
- [ ] 时钟误差、监控开销、压测端上限、空载噪声校准；
- [ ] Planned Path、允许 fallback、禁止路径和 Host Touch 预算声明；
- [ ] ActualPathReceipt、Completion/Fence/Integrity/Ready 采集可用；
- [ ] 原始输出目录、checksum、分析器版本和日志保留策略有效；
- [ ] 环境清理、故障回收和安全边界通过冒烟。

## 2. 单次运行检查表

### 2.1 运行前

- [ ] Manifest schema 校验通过，ID 未重复；
- [ ] 环境摘要与冻结版本一致；
- [ ] 上一 case 的对象、Lease、Descriptor、队列、限速和故障状态已清理；
- [ ] 温度、频率、CPU/NPU/NIC/SSD 背景噪声在允许范围；
- [ ] workload checksum、样本数和分层标签正确；
- [ ] feature flags 和基线差异已打印到日志；
- [ ] 预期故障、注入窗口、期望动作和恢复检查已确认。

### 2.2 运行中

- [ ] Warmup 与正式窗口分开；
- [ ] 请求、计划、对象、路径、Rank、Fault ID 可关联；
- [ ] Trace/Metric 丢失率实时监控；
- [ ] 故障实际生效并记录开始/结束；
- [ ] Planned/Actual Path 不一致立即打 reason，不静默改路；
- [ ] 错误/过期/越权/未 Ready 对象被消费时立即停止该项并保全现场；
- [ ] 超时/水位/TPOT 触发预期 pause、fallback 或 Recompute。

### 2.3 运行后

- [ ] Drain 有界完成，无在途任务/Lease/Refcount 泄漏；
- [ ] 环境尾快照和设备错误/SMART/RAS 保存；
- [ ] 原始日志、Trace、Receipt、Host Touch、counter、Fault 记录齐全；
- [ ] 样本数、缺失率、故障覆盖和 exit status 校验；
- [ ] 生成 checksums，原始目录转为只追加；
- [ ] 失败样本和异常不被过滤；
- [ ] 环境恢复检查通过后才开始下一 case。

### 6.3 最终决策

- [ ] Go：按冻结白名单进入 P0，迁移原型资产；
- [ ] Conditional：限定模型/框架/场景/路径/水位，冻结 feature flag 和补证计划；
- [ ] No-Go：停止统一池主路径或调整架构/采购/人力；
- [ ] Not Supported：目标平台能力不足，进入支持矩阵并使用替代路径；
- [ ] Incomplete：证据不全，禁止用目标门槛替代结果。

决策必须附：范围、里程碑、人力、采购、硬件/驱动/固件反馈、开源兼容策略、对外可表达/不可表达的竞争力口径。
